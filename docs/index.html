为什么需要它

第三方 AI API 中转站（API 代理 / 聚合平台）数量很多，但质量差异极大且不透明。 开发者选型时通常只能靠"听说"和"价格"，踩坑后才发现问题——比如声称是某个旗舰模型，实际由便宜模型应答； 或者计费口径不透明，实际开销远高于预期。

本工具包把"这家稳不稳、贵不贵、是不是真模型"从主观印象变成可量化、可复现的数据。

六项检测项

检测项方法判定基准
① 模型身份一致性固定 probe × 多次采样，比对输出风格；与官方渠道对照风格跳变 → 后端可能多模型轮换
② 可用率连续请求统计 HTTP 200 占比<99% 不适合生产环境
③ 延迟分布记录每次耗时，算中位 / P95 / 最大P95 > 中位 ×3 → 存在抖动
④ 计费 token 偏差本地 tiktoken 计数 vs 服务商返回 usage偏差 <10% 正常；>20% 需追问
⑤ 上下文真实性塞入接近宣称窗口长度的输入提前报超限 → 窗口被压缩
⑥ 缓存命中计费同一长 prompt 连续两次请求，比对第二次计费缓存价通常约为标准价 10%

测不出的东西（先读这段）

  • 主观体验：输出质量好坏、风格是否合适，需要人工评估
  • 售后服务：客服响应速度与问题解决率
  • 上游政策风险：号池被封、模型下架、突然限速等运营风险
  • 长期稳定性：单次采样存在时间偏差，长期稳定性需要持续监测
  • 计费完整性：能测 token 计数是否老实，测不出倍率是否透明（需人工核对产品页）

单次检测结论不具备长期效力。建议：小额试充 → 用真实业务跑一轮 → 再决定是否长期使用。 行业整体不稳定，用多少充多少，不要大额预付。

选型硬标准（8 条）

  • 是否公开真实的可用率 / 监控数据（只说"稳定"不算证据）
  • token 计数方式、倍率、系统提示词是否计费——必须写在明面上
  • 缓存价格：正常约为标准价 10%，15% 甚至 30% 会让高频场景成本翻倍
  • 模型是否标注上游来源；价格远低于市场的"旗舰模型"要警惕
  • 退款政策是否明确、是否原路退回
  • 高峰期限速阈值与并发上限是否公开
  • 运营主体是个人还是公司，有无可核验的联系方式
  • 自己跑一轮检测，看 P95 延迟与可用率
