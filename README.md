# AI API 渠道质量检测工具包

一条命令测出中转/代理站是否：**模型身份错配、计费 token 异常、稳定性不达标、上下文被阉割**。
检测项、判定标准与原始结果全部开源，**标准对所有站点一致（包括我们自己）**。

> 最近复测：2026-09-15 ｜ 下次计划复测：2026-10-15

---

## 这是什么

第三方 AI API 中转站（API 代理/聚合平台）现在非常多，但**质量差异极大且不透明**。开发者在选型时通常只能靠"听说"和"价格"，踩坑后才发现问题。

本工具包做两件事：

1. **提供可复现的检测脚本**——把"哪家靠谱"从主观印象变成可量化数据；
2. **公开我们的检测标准与输出格式**——你可以拿去测任何站点，包括我们自己对标的站点。

**不推荐任何具体平台，不做排名，不接受付费收录。**

## 快速开始

```bash

pip install requests tiktoken

# 一条命令跑完整检测
python check.py --base https://your-provider.example/v1 --key sk-xxx --model claude-sonnet-4-5 --n 100
```


## 检测项明细

| 检测项 | 方法 | 判定基准 | 需要的采样量 |
|--------|------|---------|-------------|
| **① 模型身份一致性** | 固定 probe × 多次采样，比对输出风格/句长分布/术语习惯；与官方渠道对照 | 风格跳变 → 后端可能多模型轮换 | ≥3 probe × ≥3 次 |
| **② 可用率** | 连续请求统计 HTTP 200 占比 | <99% 不适合生产 | ≥100 次，建议分时段（白天/深夜各一轮） |
| **③ 延迟分布** | 记录每次请求耗时，算中位/P95/最大 | P95 > 中位 ×3 → 存在抖动，可能共享池 | 同上 |
| **④ 计费 token 偏差** | 本地 tiktoken 计数 vs 服务商返回 `usage` | 偏差 <10% 正常；>20% 需追问口径 | ≥5 次取均值 |
| **⑤ 上下文真实性** | 塞入接近宣称窗口长度的输入，验证是否完整处理 | 提前报 `context length exceeded` → 窗口被压缩 | 1 次即可 |
| **⑥ 缓存命中计费**（可选扩展） | 同一长 prompt 连续两次请求，比对第二次的 usage 与计费 | 缓存价通常是标准价的 10% 左右 | 2 次 |

**判定标准对任何站点一致**。如果你认为某条标准不公平，欢迎开 Issue 反驳，我们会公开回应并说明是否调整。

## 方法与原始数据

- **采样方法**：固定 `temperature=0` + 固定 probe + 固定间隔（默认 0.3s），减少随机性干扰
- **样本规模**：默认 100 次请求；多站点对比时建议统一采样时段（避免高峰期差异混入）
- **数据落盘**：`check.py --json-out` 输出结构化 JSON，字段包括可用率、延迟分位、计费偏差、失败样本类型
- **复现**：脚本无隐藏逻辑，全部检测逻辑在 `check.py` 内可见可改

**关于"自家数据"**：我们本身运营 AI API 中转服务，因此会用自己的服务做基线测试。**基线数据与判定标准一并公开，任何人都可以用同样的脚本复测我们**——如果我们的数据不达标，同样是问题。

## 局限性（重要，请先读）

这个工具能测**技术指标**，测不出以下东西：

| 测不出 | 说明 |
|--------|------|
| 主观体验 | 输出质量好坏、风格是否合适，需人工评估 |
| 售后服务 | 客服响应速度、问题解决率 |
| 上游政策风险 | 号池被封、模型下架、突然限速等运营风险 |
| 长期稳定性 | 单次采样存在时间偏差，长周期稳定性需要持续监测 |
| 计费完整性 | 能测 token 计数是否老实，测不出"倍率是否透明"（需人工核对产品页） |
| 反爬干扰 | 部分站点对高频请求有 IP 限制，可能造成**误报**（表现为可用率偏低） |

**单次检测结论不具备长期效力。** 我们建议：小额试充 → 用自己的真实业务跑一轮 → 再决定是否长期使用。

## 选型硬标准（8 条，买之前逐条核对）

1. **稳定性证据**：是否公开真实的可用率/监控数据？（只说"稳定"不算证据）
2. **计费口径**：token 怎么计数、倍率多少、系统提示词是否计费——必须写在明面上
3. **缓存价格**：正常应约为标准价的 10%；若收 15% 甚至 30%，高频写代码场景成本会翻倍
4. **模型真实性**：是否标注上游来源（官方 Key / 号池 / 逆向）；价格远超便宜的"Opus"要警惕
5. **退款政策**：是否明确、是否走原路退回
6. **并发与限速**：高峰期限速阈值、并发上限是否公开
7. **运营主体**：个人还是公司运营；有无可核验的联系方式
8. **响应速度**：自己跑一轮 `check.py`，看 P95 延迟和可用率

**行业不稳定，建议用多少充多少，不要大额预付。**

## 常见坑（实测与社区反馈汇总）

- **缓存命中率不透明**：写代码场景大量命中缓存，缓存计费比例直接决定实际成本
- **"低价 Opus"**：价格显著低于市场时，常见解释是模型替换（用便宜模型应答）或降智版本
- **按次 vs 按量**：按次计费在长输出场景可能更贵，短输出场景更便宜，要看自己的业务形态
- **token 计数口径**：有的平台把系统提示词、历史上下文全部计入，实际开销高于预期
- **无退款政策**：出现问题时用户没有退出通道

## 常见问题

**Q：为什么不直接给一个"推荐榜单"？**
A：榜单通常掺杂商业利益，且时效性差。工具 + 标准 + 自己动手测，结论才属于你自己。

**Q：检测会不会消耗额度？**
A：会，但很少。100 次 `max_tokens=5` 的请求 + 1 次长上下文请求，成本通常在几分钱量级。

**Q：能测非 OpenAI 兼容协议的接口吗？**
A：当前脚本只支持 OpenAI 兼容格式（`/v1/chat/completions`）。Anthropic 原生协议、Gemini 原生协议的适配欢迎 PR。

**Q：你们自己的服务测出来什么样？**
A：见上方"快速开始"的示例输出。我们用同一套脚本、同一套标准；如果你复测出不同结果，请提 Issue，我们会核对并公开回应。

**Q：为什么叫"渠道质量"而不是"中转站评测"？**
A：因为这套方法对官方 API、自建代理、聚合平台都适用，检测的是"渠道"这个抽象层。
